## 1. 先记住这是什么

这是一个 **Next.js 全栈 Web 应用**，不是阅读器，也不是传统算命工具，而是一个用数据、概率和规则帮助用户做人生决策的「人生作战室」。

核心产品结构：**7 个模块 + 1 条个性化时间轴**。

阅读路径：

```text
时间轴 ★ → 01 名字 → 02 职业 → 03 规律 → 04 窗口 → 05 努力 → 06 运气 → 07 命运 → 回到时间轴
```

## 2. 接手第一步：先让静态页面跑起来

环境要求：Node.js >= 20.9，pnpm >= 9。

```bash
pnpm install
pnpm dev
```

浏览器打开：`http://localhost:5000`

只看静态页面时可以先不配置数据库；但以下能力必须配置 `.env.local` 才能用：登录、邀请码、开发者后台、内置 AI。

```bash
copy .env.example .env.local
```

需要的环境变量：

- `SUPABASE_URL`
- `SUPABASE_ANON_KEY`
- `SUPABASE_SERVICE_ROLE_KEY`
- `AI_API_URL`
- `AI_API_KEY`
- `AI_MODEL`
- `DEV_PASSWORD`
- `SESSION_SECRET`

数据库表结构：执行 `supabase/schema.sql`。

## 5. 改动前先看什么

1. 改模块顺序、编号、配色或首页导览：先看 `src/lib/module-identity.ts`。
2. 改窗口/职业/运气/规律数据：先确认 id 唯一、枚举值一致、解析格式不变。
3. 改登录、邀请码、后台：先看 `src/lib/session.ts`、`src/lib/rate-limit.ts` 和对应 `src/app/api/` 路由。
4. 改 AI：先看 `src/lib/ai-stream.ts`、`src/lib/ai-providers.ts` 和 `src/app/api/ai/`。
5. 改页面头部或滚动进场：优先复用 `ModulePageHead`、`Reveal`、`fig-kit`，不要重新手写一套。
6. 改本地状态：优先使用 `usePersistedState`；不要在 SSR 首帧直接读取 localStorage。

## 7. 当前明确知道、但没有擅自扩大范围处理的事项

- Supabase 三件套没有提供时，登录、邀请码、后台接口会失败；这是环境未配置，不是静态页面故障。
- Supabase service role key 仍在服务端使用，长期应进一步收紧数据库 RLS 和服务端权限边界。
- AI 流式面板仍有多处页面实现，后续可抽成公共 `AiStreamPanel`，但不应在接手时顺手大范围重构。
- **测试期临时全开放**：`src/contexts/auth-context.tsx` 的 `canAccessModule()` 现在无条件返回 `true`。  
  这只是为了当前测试，不是正式权限模型；商业化/邀请码收口前必须恢复按角色判断。
- `scripts/archive/` 中的脚本是历史资料，除非明确需要重生成数据，不要运行。
